# Decisions and assumptions

Every deviation from the spec or the plan, and every assumption, is recorded here.
Newest phase first within each section.

## Gameplay and product (from PLAN §5, approved before implementation)

| Topic              | Decision                                                                                                                                                                                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mobile orientation | Landscape only for gameplay; portrait = rotate overlay + auto-pause. Menus usable in both.                                                                                                                                         |
| Keyboard           | Forward `W`/`↑` · turn `A`/`←`, `D`/`→` · front fire `Space` (also `K`) · broadside left `Q` (`J`) · right `E` (`L`) · pause `P`/`Esc`. Captured only while phase = running.                                                       |
| Touch              | Bottom-left: turn left / forward / turn right; bottom-right: fire left / front / right (mockup); pause top-right. Multi-touch via pointer events, hold-to-act.                                                                     |
| Movement           | Forward only (no reverse, per spec); acceleration/deceleration; rotation allowed at any speed.                                                                                                                                     |
| Session time       | 60–180 s, step 10 s, default 120 s.                                                                                                                                                                                                |
| Spawn interval     | 1.0–10.0 s, step 0.5 s, default 3 s. Safety cap of 25 alive enemies. A due spawn is never dropped: if blocked (cap / no valid point) it stays pending and is retried on following steps; cadence stays anchored to `n × interval`. |
| Spawn distribution | 50 % Chaser / 50 % Shooter (seeded); first two spawns forced one of each. Initial spawn at t = interval.                                                                                                                           |
| Spawn points       | Random points on a ring 60 u inside the border, ≥ 320 u from player, circle r = 70 clear of islands/ships; up to 12 attempts per step, otherwise retry next step.                                                                  |
| Player             | HP 200 (rebalanced, DECISIONS S17), speed 140 u/s, accel 160 u/s², turn 150°/s.                                                                                                                                                    |
| Weapons            | Front: dmg 20, cd 0.5 s. Broadside (each side independent): 3 balls, spacing 28 u, dmg 15 each, cd 1.5 s. Projectile speed 420 u/s, range 380 u.                                                                                   |
| Chaser             | HP 30, speed 105 u/s, turn 120°/s, ram damage 20 (rebalanced, DECISIONS S17).                                                                                                                                                      |
| Shooter            | HP 50, speed 90 u/s, turn 90°/s, range 300 u, standoff 220 u, dmg 7, cd 2.5 s (rebalanced, DECISIONS S17), aim tolerance 12°.                                                                                                      |
| Damage stages      | HP ratio > 2/3 → 0; > 1/3 → 1; > 0 → 2; dead → 3 (wreck, 0.8 s sink fade, non-colliding). Fire effect at stage ≥ 1.                                                                                                                |
| HP bar colours     | Player: green > 50 %, amber > 25 %, red. Enemy: green > 40 %, red (no amber enemy fill in the atlas).                                                                                                                              |
| Ship colours       | Player blue (`ship_5`), Chaser black skull (`ship_2`), Shooter red (`ship_3`).                                                                                                                                                     |
| Scoring            | +1 only on `shipDestroyed` with `killer === player`; ram death = 0.                                                                                                                                                                |
| Effective duration | Active (unpaused) simulated seconds until end.                                                                                                                                                                                     |
| Ranking scope      | One entry per match; a captain may appear several times. Tab defaults to the current Options config with a selector of configs that have records.                                                                                  |
| Pause → Options    | Allowed (mockup). Changes are saved but only apply to the next match.                                                                                                                                                              |
| Dev panel          | Available in production via `?dev=1` and a discreet footer link on the main menu.                                                                                                                                                  |
| Routing            | React Router (library mode): `/`, `/options`, `/play`, `/records/:tab`, `/result`. Reload on `/play` → menu (match abandoned).                                                                                                     |
| Styling            | CSS Modules + CSS variables; atlas images via `border-image`/background; self-hosted OFL font.                                                                                                                                     |
| Missing UI assets  | No hover/disabled for secondary buttons, no disabled round button, no focus states, no mute/help icons: derived via CSS (filters, our own focus ring) and small inline SVGs matching the style.                                    |

## Phase 2 — assets and PixiJS rendering

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **2× ship atlas: 1× fallback.** `pnpm assets:build` rasterizes `assets/vector/ships_miscellaneous_vector.svg` at 2× with **`@resvg/resvg-js`** (dev dependency: a maintained, dependency-free SVG renderer with prebuilt binaries for Windows and Linux, no native build step) and compares every frame, box-filtered back to 1×, with the raster sheet at its XML coordinates (tolerance 8/255 per channel). The SVG is a 1280×720 overview in the `preview.png` layout, not the 1024×512 sheet layout, so all 102 frames mismatch and the build ships the 1× sheet only; the result is written to `public/assets/manifest.json` and guarded by `tests/tooling/vectorAtlas.test.ts`. Locating each sprite in the overview by template matching is a possible follow-up.                                                                                                                                                                                                                                                                                                                                                              |
| R2  | **Map change.** The L island's one-tile step (row 5) needs an edge and a concave corner in one tile, which the shore tile sets do not have. Row 4 of the L now spans cols 10–13 (+2 island cells). `validateMap` gained a rule backed by `shoreShape` (core): every island cell must map to one fill/edge/outer/inner-corner tile, so art and collision can never drift apart again.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| R3  | **Tile set and padding.** Islands use the sand-with-grass set (6–9/22–25/38–41/54–57); the "sand clearing" tiles 36/37/52/53 serve as concave corners (their borders line up with the edge tiles, checked pixel by pixel). Shallow water (10–12/26–28/42–44, concave 58/59/74/75) rings every island by one tile; where two rings meet in an undrawable step the mask is grown until drawable. The tile sheet has no spacing, so the build re-packs it with 2 px (4 px at 2×) of edge extrusion: linear filtering at non-integer scales no longer samples neighbouring tiles (seams).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| R4  | **Collision vs shore art.** Measured on the tiles: straight shores lie 0–3 px (mean 1.5) inside the tile edge → `arena.islandCollisionInset` stays **0**. The rounded corners fit a circle; a square collision corner left up to 24 px of water between hull and sand on the diagonal. New `arena.islandCornerRadius` = **61**: best single radius against the corner tiles (max 4.0 px of water and 4.0 px of sand overlap anywhere on the arc, ≈ 2.7 px near the diagonal; 59 → 4.4 px gap, 62 → 4.4 px overlap). Only convex shore corners are rounded (an island cell whose two outer neighbours are water — exactly the cells drawn with corner tiles, tested); junctions between rects of one island stay square, so nothing can tunnel there. Ships (circle vs corner circle) and balls (swept, exact against the convex rounded rect) use the same shape; spawner, steering feelers and line of sight too. Side effect: the naive bot no longer gets trapped on square corners, so the bot test stopped comparing Chaser rams (BALANCE re-run: skilled median 89.4 → 93.4 s, time_up 6 → 4 %; naive 90.5 → 98.9 s, 4 → 24 %). |
| R5  | **Render reads, never decides**: views take `DeepReadonly<World>`; a Node unit test renders a deep-frozen world. Effects/sounds come only from `DomainEvent`s through pure mappings; positions interpolate with the stepper alpha; ship views, balls, effects and HP bars are pooled. Enemy bars: `enemy_health_frame` at 0.4 (64 px wide over a 66 px ship), green > 40 % else red; player bar: `health_frame` at 0.3 with green/amber/red. Fill clipped by its texture frame from `ui.layout.fill_rect` (no masks, so bars batch).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| R6  | **Render-side constants** (frames, effect timings, bar scales, shake) live in `src/game/render/theme.ts`: presentation, not balancing, so they stay out of `GameConfig`. Effects and water drift advance by the session clock, so a paused/manual clock freezes them too.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| R7  | **Assets**: one Pixi bundle (`combat`) from a generated `manifest.json`, loaded once per page; `@2x` variants chosen when `devicePixelRatio × viewport scale > 1` (fixed at the first load). A failed load is not cached by Pixi, so Retry just loads again; combat never starts before the art. Asset-failure e2e uses `browserContext.route` (MSW's service worker forwards asset requests itself, which `page.route` does not see) — no special production code path.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| R8  | **Lifecycle**: session boot is abort-aware; Pixi v8 `init` cannot be cancelled, so an aborted init destroys its app before attaching the canvas. Resource counters (apps, ticker callbacks, listeners, observers, dynamic textures, audio loops; plus canvases, display objects, cached textures in the report) are always on (integer bookkeeping) and exposed via `?test=1`. Strict Mode is tested against the Vite dev server (Playwright project `dev-strict-mode`) because production builds never double-mount.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| R9  | **Dev layer** `src/dev` (sandbox): may import the test-only bots (`mayImportTestSupport`), nothing may import it (`devOnly`, incl. `main.tsx`); `sandbox.html` is not a Vite input and `scripts/verify-dist.mjs` fails the build if `src/dev/`, `game/core/testing/` or the sandbox page shows up in `dist/` (source maps keep module paths).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| R10 | **Lazy-loaded game screen and test hook**: `GameScreen` is `React.lazy`, and `main.tsx` imports the test hook dynamically only with `?test=1`, so Pixi (~0.3 MB min) is not in the menu's entry chunk (223 kB).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| R11 | **Audio** after a user gesture only (or `userActivation.hasBeenActive`), decoded in the background; missing buffers are skipped, failures warn once. Mute persistence and its toggle come with the Options/HUD UI (Phase 4).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| R12 | **Placeholder UI**: until Phase 4 the menu is a Play button and the game screen has a Main menu button; the player ship stays idle until Phase 3 input.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| R13 | **E2E arena timeout 15 s**: WebGL starts on a software rasterizer in headless Chromium (~1 s alone, several seconds with parallel workers and two web servers; asset loading ~0.1 s).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

## Phase 1 — simulation core

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| S1  | **Coordinates**: world 1024×576 u, y down; `heading` in radians with forward = `(cos h, sin h)`. Sprites point up, so render adds π/2. Port (left) = `h − π/2`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| S2  | **Units**: config uses u, u/s, u/s², seconds and **degrees** (readable balancing); degrees are converted to radians once in `createMatch` (`world.angles`), never per step.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| S3  | **Fixed stepper lives in `game/core/stepper.ts`**, not `runtime/loop.ts` (PLAN §2.1): the accumulator is a pure rule and the 30/60/144 Hz parity test must cover it. `Clock` + `ManualClock` are in `shared/`, `realClock` (`performance.now`) in `platform/`. Runtime only wires it to the ticker.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| S4  | Time = `stepCount × stepSeconds`; boundary comparisons use `EPSILON`. The stepper uses a 1e-6 ms tolerance so float frame timestamps give exact step counts. Past `maxStepsPerFrame` (8) the backlog is dropped (slow motion below ~8 fps).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| S5  | **Step order**: input → AI → movement → rams → separation/island push-out → weapons → projectiles → cleanup → end checks → spawner. **Death is checked before time**: HP 0 on the step the time runs out ⇒ `defeated`. No spawn happens on the ending step.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| S6  | **Hull** = two overlapping circles r 24 at ±18 u (the planned r≈24 at ±28 left a gap amidships through which balls could pass; validation now requires offset < radius).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| S7  | **No friendly fire**: projectiles only hit the other team; enemy balls pass through enemy ships without damage or removal. Chaser–player contact is a ram (not separated): chaser destroyed (no score), player takes `ramDamage`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| S8  | **Navigation**: BFS flow field over water cells (recomputed only when the player changes cell), direct seek with a hull-wide line of sight, 3 feelers for local avoidance applied only while the target is ahead (otherwise the bias near ±180° flips the turn every step and ships stall in pockets).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| S9  | **Shooter fires only with line of sight** (segment to the player clear of islands, padded by the ball radius) besides range, aim tolerance and cooldown. Standoff = stop and face the player.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| S10 | **Map**: hand-authored 16×9 grid with a "U" island (concave pocket) and an L-shaped island (widened in Phase 2, R2). `validateMap` (unit-tested) requires 2×2-composable islands, channels ≥ 2 tiles, no diagonal-only contacts, connected water. `arena.islandCollisionInset` (default 0) shrinks only water-facing rect sides; convex corners are rounded (R4).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| S11 | **Spawner backlog**: due = `floor((elapsed + ε) / interval)`; pending spawns retry every step within `attemptsPerStep` placement attempts and the alive cap; never dropped, cadence never shifted. Spawn points lie on a ring 60 u inside the border.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| S12 | **No magic numbers in core**, enforced by ESLint `@typescript-eslint/no-magic-numbers` on `src/game/core` (tests and `testing/` helpers excluded); shared constants `TAU`, `HALF`, `EPSILON`, `MS_PER_SECOND`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| S13 | **Coverage gate**: `pnpm test` = `vitest run --coverage` with a 90 % line threshold on `src/game/core/**` (CI runs `pnpm test`). `test:coverage` script removed as redundant.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| S14 | `createMatch(cfg, seed, { spawnEnemies: false, map })` exists for isolated unit tests and tooling only; never reachable from the UI or the test hook.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| S15 | **Balance tool**: `pnpm balance` runs `scripts/balance.ts` directly with Node's type stripping and loads the app modules through Vite's `runnerImport` (no new dependency). Runs every bot profile (naive, skilled) on the same seeds; results and tuning history in S17–S18.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| S16 | Destroyed ships stay as non-colliding wrecks for `damage.wreckSeconds` (render plays the sink); the player's wreck is never removed. Wrecks still block spawn points.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| S17 | **Rebalance (Phase 1 follow-up)**. Session 120 s, spawn interval 3 s and player weapons kept (mockups). The three prescribed steps (Chaser speed, spawn mix, ram damage) were applied and kept, but left the skilled median at 36.6 s with 0 % time_up. **Target revised** from 60–100 s / 20–50 % time_up to **60–110 s / 15–50 %** (skilled bot, default config, seeds 1–50): the earlier what-ifs (S18) showed no variant could meet both original bounds at once (≥ 20 % time_up only came with medians > 100 s), so the window was widened to what a 120 s session can plausibly produce while still ending most matches before time runs out. Then a grid on the suspected root cause, undodgeable Shooter fire: Shooter ball speed 280 / 320 u/s × player HP 150 / 175, Shooter cooldown 2.2 s. **No grid variant met the revised target** (all 0 % time_up, medians 54–65 s); a control at the original 420 u/s gave nearly the same numbers, so slower balls barely help: the bots never steer away from incoming balls, and the gain came from the cooldown and HP. **Fallback variant A applied**: player HP 200, Shooter dmg 7, cd 2.5 s, ball speed unchanged (420 u/s) → skilled median 89.4 s, **6 % time_up, still below the revised 15 %**. See the table below. Final tuning will be validated by manual play in Phases 3–4 (a human dodges, unlike the bots, so ball speed is worth retesting there). |
| S18 | **What-ifs before the revision** (read-only runs, skilled bot, seeds 1–50): A player HP 200 + Shooter dmg 7, cd 2.5 s → 89.4 s, 6 % time_up (now the default, S17) · B HP 250 + Shooter 7 / 2.5 s → 110.8 s, 24 % · E HP 200 + Shooter 5 / 3.0 s → 113.7 s, 28 % · F E + ram 15 → 120 s, 60 % (overshoot). B is just outside the revised duration bound and E further out; both remain candidates if manual play finds A too punishing. The skilled bot outlasts the naive one only marginally in every variant.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| S19 | **Bots are test support only**: `src/game/core/testing` is its own lint layer (`coreTesting`, `testOnly`). Only `*.test.ts(x)` files and `scripts/` (outside every layer) may import it, so the bots can never be exported from `core/index.ts` or bundled into the app. The boundary rule now resolves nested layers by the longest matching directory. Skilled-bot constants (0.2 s reaction time, 200 u kite standoff, …) were fixed before tuning and never adjusted to the target.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

## Phase 0 — tooling

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                         |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | **pnpm 10** pinned via `packageManager`. `corepack enable` needs admin on this Windows machine (writes to `Program Files`), so pnpm was installed with `npm i -g pnpm@10`; CI and Docker use corepack.                                                                                                                                                                           |
| T2  | **Generated assets are not committed.** `public/assets/` is git-ignored; `pnpm assets:build` is invoked explicitly by `dev`, `build` and `e2e:serve` (no pre/post hooks, which pnpm does not run reliably). A clean checkout works because the sources in `assets/` are versioned. The script is deterministic and idempotent (verified by building twice and comparing hashes). |
| T3  | **Layer boundaries via a local ESLint rule** instead of `eslint-plugin-import-x` `no-restricted-paths` (planned): import-x only reports imports that resolve on disk, so it cannot guard empty layers or probe sources, and it pulls a native resolver. The local rule is ~100 lines, has no dependencies and is unit-tested.                                                    |
| T4  | **`shared/` is pure; browser adapters go to a new `platform/` layer** (storage, visibility, uuid…). Core and config may import `shared` but never `platform`; enforced by the lint rule and by `tsconfig.core.json` (no DOM lib).                                                                                                                                                |
| T5  | **TypeScript 6.0**, not 7: `typescript-eslint` 8.x supports `<6.1`. Pinned with `~6.0.3`.                                                                                                                                                                                                                                                                                        |
| T6  | **ESLint 10** with `eslint-plugin-jsx-a11y` 6.10, whose peer range stops at ESLint 9. Verified the plugin's rules run correctly on ESLint 10 and allowed the version via `pnpm.peerDependencyRules` (ESLint 9 is end-of-life). Same for `@vitest/mocker`'s optional `msw@^2` peer (we use MSW 3).                                                                                |
| T7  | **MSW 3** (current major). API changes vs v2 used here: `onUnhandledFrame` replaces `onUnhandledRequest`. The mock layer is imported lazily from `main.tsx` so it ships in its own chunk (~150 kB gzip); revisit size in Phase 8.                                                                                                                                                |
| T8  | Ship atlas: the delivered "retina" ship sheet is byte-for-byte the same geometry as 1×, so only the 1× sheet is shipped. Rasterizing a 2× atlas from the SVG was tried in Phase 2 (R1): the vector layout does not match, 1× kept.                                                                                                                                               |
| T9  | Tile atlas numbering is row-major over the 16×6 sheet (`tile_1` top-left); verified pixel-by-pixel against all 96 `tile_N.png` in both resolutions (`pngjs` dev dependency, test only).                                                                                                                                                                                          |
| T10 | Vite `build.assetsDir = 'static'` so hashed bundles don't share `dist/assets/` with the runtime game assets.                                                                                                                                                                                                                                                                     |
| T11 | Pixi, TanStack Query, Axios and React Router are installed in the phase that first uses them, to keep each phase's dependency changes reviewable.                                                                                                                                                                                                                                |
| T12 | Playwright snapshots use `{testDir}/__screenshots__/{testFilePath}/{projectName}/{arg}{ext}` (no OS suffix); baselines only come from the pinned Linux image. A unit test keeps the CI image tag equal to the installed `@playwright/test` version.                                                                                                                              |
