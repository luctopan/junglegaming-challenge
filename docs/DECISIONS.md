## Gameplay and product (from PLAN §5, approved before implementation)

| Topic              | Decision                                                                                                                                                                                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mobile orientation | Landscape only for gameplay; portrait = rotate overlay + auto-pause. Menus usable in both.                                                                                                                                         |
| Keyboard           | Forward `W`/`↑` · turn `A`/`←`, `D`/`→` · front fire `Space` (also `K`) · broadside left `Q` (`J`) · right `E` (`L`) · pause `P`/`Esc`. Captured only while phase = running.                                                       |
| Touch              | Bottom-left: turn left / forward / turn right; bottom-right: fire left / front / right (mockup); pause top-right. Multi-touch via pointer events, hold-to-act.                                                                     |
| Movement           | Forward only (no reverse, per spec); acceleration/deceleration; rotation allowed at any speed.                                                                                                                                     |
| Session time       | 60–180 s, step 10 s, default 120 s.                                                                                                                                                                                                |
| Spawn interval     | 1.0–10.0 s, step 0.5 s, default 3 s. Safety cap of 25 alive enemies. A due spawn is never dropped: if blocked (cap / no valid point) it stays pending and is retried on following steps; cadence stays anchored to `n × interval`. |
| Spawn distribution | 50 % Chaser / 50 % Shooter (seeded); first two spawns forced one of each. Initial spawn at t = interval.                                                                                                                           |
| Spawn points       | Random points on a ring 60 u inside the border, ≥ 320 u from player, circle r = 70 clear of islands/ships; up to 12 attempts per step, otherwise retry next step.                                                                  |
| Player             | HP 200 (rebalanced, DECISIONS S17), speed 140 u/s, accel 160 u/s², turn 150°/s.                                                                                                                                                    |
| Weapons            | Front: dmg 20, cd 0.5 s. Broadside (each side independent): 3 balls, spacing 28 u, dmg 15 each, cd 1.5 s. Projectile speed 420 u/s, range 380 u.                                                                                   |
| Chaser             | HP 30, speed 105 u/s, turn 120°/s, ram damage 20 (rebalanced, DECISIONS S17).                                                                                                                                                      |
| Shooter            | HP 50, speed 90 u/s, turn 90°/s, range 300 u, standoff 220 u, dmg 7, cd 2.5 s (rebalanced, DECISIONS S17), aim tolerance 12°.                                                                                                      |
| Damage stages      | HP ratio > 2/3 → 0; > 1/3 → 1; > 0 → 2; dead → 3 (wreck, 0.8 s sink fade, non-colliding). Fire effect at stage ≥ 1.                                                                                                                |
| HP bar colours     | Player: green > 50 %, amber > 25 %, red. Enemy: always red, as in the mockup (revised in Phase 2 polish, R17).                                                                                                                     |
| Ship colours       | Player blue (`ship_5`), Chaser black skull (`ship_2`), Shooter red (`ship_3`).                                                                                                                                                     |
| Scoring            | +1 only on `shipDestroyed` with `killer === player`; ram death = 0.                                                                                                                                                                |
| Effective duration | Active (unpaused) simulated seconds until end.                                                                                                                                                                                     |
| Ranking scope      | One entry per match; a captain may appear several times. Tab defaults to the current Options config with a selector of configs that have records.                                                                                  |
| Pause → Options    | Allowed (mockup). Changes are saved but only apply to the next match.                                                                                                                                                              |
| Dev panel          | Available in production via `?dev=1` and a discreet footer link on the main menu.                                                                                                                                                  |
| Routing            | React Router (library mode): `/`, `/options`, `/play`, `/records/:tab`, `/result`. Reload on `/play` → menu (match abandoned).                                                                                                     |
| Styling            | CSS Modules + CSS variables; atlas images via `border-image`/background; self-hosted OFL font.                                                                                                                                     |
| Missing UI assets  | No hover/disabled for secondary buttons, no disabled round button, no focus states, no mute/help icons: derived via CSS (filters, our own focus ring) and small inline SVGs matching the style.                                    |

## Phases 5–6 — API layer and mock backend

| #   | Decision                                                                                                                                                                                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A1  | **Axios + TanStack Query** added in Phase 5 (T11): Axios for the timeout, `AbortSignal` support and uniform errors; TanStack Query for cache, retries, background refetch and cancellation. Response bodies are checked by small hand-written guards (`src/api/guards.ts`), no schema library.         |
| A2  | **Retry policy**: at most 2 retries with 0.5 s → 1 s backoff, only for `timeout`, `network`, 5xx and 429 (`isRetryable`). 4xx and contract violations fail at once.                                                                                                                                    |
| A3  | **Out-of-order protection**: superseded requests are cancelled through the query's `AbortSignal` (primary); each page carries a server `revision` and an older page never replaces a newer cached one (secondary). The revision is stored apart from the mock db so Reset never moves it backwards.    |
| A4  | **Submission states**: `pending` = retryable failure (resent on start, `online`, Retry, after any success); `failed` = 4xx (resent only by Retry). Both show Retry on the Result screen; neither ever blocks Play again. Unknown and not queued = already confirmed.                                   |
| A5  | **Submission runs outside React** (`SubmissionService` over TanStack's `MutationObserver`): the app-start flush happens before any screen mounts, and a match keeps being sent after its Result dialog closes. Single flight per `matchId` in memory; the server's idempotent PUT covers tabs/refresh. |
| A6  | **Fixtures are not stored in the mock db**: the scenario adds them at read time (`success`: 23 fixtures, `multi-page`: +180, `empty`: none). The db only holds matches this browser registered, so Reset is "delete one key" and fixtures can never drift.                                             |
| A7  | **Dev panel talks to the mock over HTTP** (`/api/__mock/{status,scenario,recover,reset}`, never affected by scenarios), so the UI does not import the mock layer and the layer rules hold. It ships in production on purpose (demo).                                                                   |
| A8  | **Scenario persistence**: `?scenario=` wins and is stored in `sessionStorage` (per tab, survives reloads); the dev panel changes it at runtime. `unavailable-then-recover` fails the first 3 writes (the request and its 2 automatic retries), so the Result shows Pending and Retry then succeeds.    |
| A9  | **Timeout in tests**: `?apiTimeout=<ms>` is honoured only with `?test=1`; `VITE_API_TIMEOUT_MS` sets it at build time (default 8 s). `timeout` scenarios never answer, so they need no latency scaling.                                                                                                |
| A10 | **Pagination shows the requested page**, not the page of the data on screen: while a page loads, the previous rows stay (placeholder) and a second Next click goes one further instead of re-requesting the same page.                                                                                 |

## Phase 3 — input, pause and session lifecycle

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I1  | **Keys by `KeyboardEvent.code`**, never `key`: the physical position decides, so AZERTY/ABNT layouts, Caps Lock and Shift change nothing. Ctrl/Alt/Meta combinations stay the browser's (no hijacked shortcuts). Game keys are prevented only while the match runs; a captured keydown's keyup is prevented too, so a key released after pausing cannot activate the focused Resume button.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| I2  | **Auto-repeat never acts** (swallowed: prevented, no effect). Held actions are already held; the pause key cannot toggle in a loop; and a key held through a pause does not resume moving or firing after Resume until it is released and pressed again. The pause dialog applies the same rule to its own Escape/P.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| I3  | **Held state per source** (`key:<code>`, `pointer:<id>`), so W+↑ or two fingers on one action release correctly, and moving + firing is natural. **Taps are latched** until the next simulation sample, so a press shorter than one 1/60 s step still acts once. Opposite turns cancel.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| I4  | **Touch = pointer events with pointer capture**, delegated from the game screen to buttons tagged `data-game-action` (React keeps no input state). Release on `pointerup`, `pointercancel` and `lostpointercapture`; `contextmenu` prevented; CSS `touch-action: none`, no selection or long-press callout. The controls are shown on every device, as in the mockup (they also work with a mouse), and stay out of the tab order (keyboard players have the keys).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| I5  | **Pause model** in a DOM-free `MatchDriver` (runtime): paused ⇒ the stepper is not ticked (timer, cooldowns, AI, spawns frozen). Pause and resume both clear held input; resume resets the stepper baseline, so paused wall time never reaches the accumulator. The first frame after Resume only sets the baseline (≤ 1 frame of play time not simulated, by design). The first pause reason wins (a blur during a manual pause stays "manual").                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| I6  | **Auto-pause** on window `blur` and on `visibilitychange` → hidden, and a match that starts in a hidden tab starts paused. Focus or visibility coming back never resumes: only the Resume button or a fresh Esc/P. Effects, water and shake freeze; audio is silenced via the output gain (the ambience keeps its place).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| I7  | **Restart (Play again) reuses the session's Pixi app** (PLAN §2.8) but builds a new `MatchDriver`: fresh world, stepper, input and pause state, no pending events; views return to their pools. Leaving the screen destroys the whole session (counters back to 0, checked over repeated play/exit cycles). A test seed overrides the UI's random restart seed, so e2e replays are deterministic.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| I8  | **Abandon = destroy before `matchEnded`.** Main menu, leaving the screen and reload all destroy the session; no result object exists for an unfinished match, so Phase 5 (which records on `matchEnded` only) can never record it. The e2e check also asserts no `/api` write and no new storage key.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| I9  | **HP bars stay inside the arena**: above the ship, below it when the top has no room, then clamped to the edges (`placeHpBar`, pure). The arena rect is used because `fitViewport` always shows it entirely.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| I10 | (Superseded by Phase 4.) **Temporary HUD and dialogs** (text HUD, pause dialog with Resume/Main menu, end panel with Play again/Main menu) until Phase 4 restyles them, adds Options to the pause menu, the Result screen, the focus trap and the live region. The HUD is memoised and fed only by the bridge's match snapshot; its commits are counted (`platform/commitCounters`) for the e2e render-count check.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| I11 | **Test hook**: `setSeed`/`?seed=`, `useManualClock`/`?clock=manual`, `advance(ms)` (real frame function in 60 Hz frames), `snapshot()`, `resources()`, `hudCommits()`. Overrides are read by `createGameSession` from `runtime/testControls` (null outside test mode). MSW scenario selection joins in Phase 6.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| I12 | **Dev-only balance overrides** `?cfg.<path>=<value>` (numbers/booleans of `GameConfig`, arrays by index), applied in order, each validated with `validateGameConfig` against the config so far; invalid ones are ignored with a `[dev config]` console warning. Guarded by `import.meta.env.DEV` so Rollup drops the module from production; `verify-dist` fails the build on its source path (source maps) or its log text (emitted JS only, since source maps embed the dead branch of `matchConfig.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| I13 | **Playwright workers: 4 locally, 2 in CI.** Each game page renders WebGL on the CPU (SwiftShader) at 60 fps; with the default (half the cores = 10 here) pages starved each other into start-up timeouts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| I14 | **Multi-touch e2e through CDP** `Input.dispatchTouchEvent` (Chromium emits real touch pointer events; Playwright's touchscreen only taps). A `touchEnd` releases the points it lists. Touch specs run on the mobile project only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| I15 | **CI e2e fix: render only when a frame can change.** Cause (CI run 37602573008, reproduced with `pnpm test:e2e:docker --cpus=2`, the 2-vCPU runner of this private repo: 7 failed + 2 flaky in 19.5 min): every game page rendered WebGL on the CPU at 60 fps even under the test manual clock and while paused, so on 2 CPUs `page.evaluate`/`advance` calls queued behind rendering and timed out. Fix: (a) under the manual clock the Pixi ticker is stopped; `advance(ms)` runs the simulation for each 60 Hz frame and renders exactly one frame at the end (effects of frames never shown are dropped; the rendered frame plays the latest events); (b) in real play a pause renders one final frame and stops the ticker until Resume (resume still resets the stepper baseline); an ended match keeps rendering so the last explosions play out. Policy in `runtime/renderPolicy.ts` (unit-tested); `framesRendered()` on the test hook; e2e:rendering asserts `advance(2000)` ⇒ 1 frame and no frames while paused. Result in the same container: 72 passed in 5.7 min. No timeout was raised. |
| I16 | **Asset build rebuilds in place** (prunes stale files at the end) instead of deleting `public/assets/` first. The prod and dev e2e web servers start in parallel; the dev server scans `public/` once at start-up, and on Docker bind mounts from Windows no file events arrive, so a file deleted during that scan stayed a 404 (served as the HTML fallback: "Unexpected token '<'" for `manifest.json`), failing the Strict Mode specs at random in the local container. Native Linux CI was unaffected (its watcher sees the recreated files).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| I17 | `pnpm test:e2e:docker --cpus=<n>` (consumed by `scripts/e2e-docker.mjs`, not forwarded) caps the container's CPUs to reproduce CI locally.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Phase 2 — assets and PixiJS rendering

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **2× ship atlas from the vector.** `pnpm assets:build` rasterizes `assets/vector/ships_miscellaneous_vector.svg` at 2× with **`@resvg/resvg-js`** (dev dependency: a maintained, dependency-free SVG renderer with prebuilt binaries for Windows and Linux, no native build step). The SVG is a 1280×720 overview in the `preview.png` layout with no sprite ids, so read as-is none of the 102 frames lines up with the 1024×512 sheet. A one-time offline script (`scripts/locate-vector-frames.mjs`, coarse search on 4×-reduced images, small frames at full 1×, refinement at half-pixel precision, ~1 min) located **95 of 102 frames**, including all 34 the game draws (ships, ball, explosions, fire, debris; worst error 6.4/255); its result is committed as `scripts/data/ships-vector-frames.json`. Not located: `crew_1…6` (error 17–23: drawn differently in the overview) and `pole` (10.4) — unused in the game, upscaled from 1× in the 2× sheet. The build re-packs the 2× raster into the 1× layout and ships `ships_sheet@2x` only if **every** frame, box-filtered back to 1×, matches the raster sheet (tolerance 8/255 per channel); otherwise it falls back to 1× (status in `manifest.json`). Guarded by `tests/tooling/vectorAtlas.test.ts`. |
| R2  | **Map change** (superseded by R15; the layout lives on as `POCKET_MAP` for system tests). The L island's one-tile step (row 5) needs an edge and a concave corner in one tile, which the shore tile sets do not have. Row 4 of the L now spans cols 10–13 (+2 island cells). `validateMap` gained a rule backed by `shoreShape` (core): every island cell must map to one fill/edge/outer/inner-corner tile, so art and collision can never drift apart again.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| R3  | **Tile set and padding.** Islands use the sand-with-grass set (6–9/22–25/38–41/54–57, see R14 for how it is laid out); the "sand clearing" tiles 36/37/52/53 serve as concave corners. Shallow water (10–12/26–28/42–44, concave 58/59/74/75) rings every island by one tile; where two rings meet in an undrawable step the mask is grown until drawable. The tile sheet has no spacing, so the build re-packs it with 2 px (4 px at 2×) of edge extrusion: linear filtering at non-integer scales no longer samples neighbouring tiles.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| R4  | **Collision vs shore art.** Measured on the tiles: straight shores lie 0–3 px (mean 1.5) inside the tile edge → `arena.islandCollisionInset` stays **0**. The rounded corners fit a circle; a square collision corner left up to 24 px of water between hull and sand on the diagonal. New `arena.islandCornerRadius` = **61**: best single radius against the corner tiles (max 4.0 px of water and 4.0 px of sand overlap anywhere on the arc, ≈ 2.7 px near the diagonal; 59 → 4.4 px gap, 62 → 4.4 px overlap). Only convex shore corners are rounded (an island cell whose two outer neighbours are water — exactly the cells drawn with corner tiles, tested); junctions between rects of one island stay square, so nothing can tunnel there. Ships (circle vs corner circle) and balls (swept, exact against the convex rounded rect) use the same shape; spawner, steering feelers and line of sight too. Side effect: the naive bot no longer gets trapped on square corners, so the bot test stopped comparing Chaser rams (BALANCE re-run: skilled median 89.4 → 93.4 s, time_up 6 → 4 %; naive 90.5 → 98.9 s, 4 → 24 %).                                                                                                                                   |
| R5  | **Render reads, never decides**: views take `DeepReadonly<World>`; a Node unit test renders a deep-frozen world. Effects/sounds come only from `DomainEvent`s through pure mappings; positions interpolate with the stepper alpha; ship views, balls, effects and HP bars are pooled. Enemy bars: `enemy_health_frame` at 0.4 (64 px wide over a 66 px ship), always red (R17); player bar: `health_frame` at 0.3 with green/amber/red. Fill clipped by its texture frame from `ui.layout.fill_rect` (no masks, so bars batch).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| R6  | **Render-side constants** (frames, effect timings, bar scales, shake) live in `src/game/render/theme.ts`: presentation, not balancing, so they stay out of `GameConfig`. Effects and water drift advance by the session clock, so a paused/manual clock freezes them too.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| R7  | **Assets**: one Pixi bundle (`combat`) from a generated `manifest.json`, loaded once per page; `@2x` variants chosen when `devicePixelRatio × viewport scale > 1` (fixed at the first load). A failed load is not cached by Pixi, so Retry just loads again; combat never starts before the art. Asset-failure e2e uses `browserContext.route` (MSW's service worker forwards asset requests itself, which `page.route` does not see) — no special production code path.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| R8  | **Lifecycle**: session boot is abort-aware; Pixi v8 `init` cannot be cancelled, so an aborted init destroys its app before attaching the canvas.
